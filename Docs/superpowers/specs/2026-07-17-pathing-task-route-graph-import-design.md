# 历史 PathingTask 路线拟合导航路网设计

日期：2026-07-17

## 背景

当前 `RouteNavigationGraphBuilder` 只能读取 `User/AutoPathing/Routes` 下的 `*_Telemetry.json`。现有地图追踪 JSON 虽然包含可执行路点，但没有任何生产代码会把这些 `PathingTask` 转换为 `route_navigation_graph.json`。PRD 中“通过历史路线构建路网”的描述因此尚未真正落地。

本设计采用已批准的方案 A：新增历史路线源适配器，将 `PathingTask` 在内存中转换为统一的导航路段，交给现有路网构建器；不生成伪遥测文件，也不建立第二套图格式。

## 首轮数据源

首轮构图直接读取脚本仓库原文件，不读取订阅后的 `H:\Auto\BetterGI\User\AutoPathing` 副本：

1. `H:\Auto\脚本仓库\bettergi-scripts-list\repo\pathing`
2. `H:\Auto\脚本仓库\bettergi-scripts-list\repo\js\AAA-Artifacts-Bulk-Supply\assets\ArtifactsPath`
3. `H:\Auto\脚本仓库\bettergi-scripts-list\repo\js\AutoHoeingOneDragon\pathing`
4. `H:\Auto\脚本仓库\BadGI-Repo\repo\pathing`

2026-07-17 的只读盘点结果如下：

| 指标 | 数量 |
| --- | ---: |
| JSON 文件 | 10,721 |
| 可识别路线 | 10,176 |
| 至少两个路点的候选路线 | 10,029 |
| 路点总数 | 114,162 |

实现阶段使用结构化 JSON 解析再次复核后，确认“至少两个路点的候选路线”实际为 10,018 条。原 10,029 是首轮启发式盘点对 11 个非候选文件的误计；独立 PowerShell 严格 JSON 解析得到 10,017 条，另有 1 条合法路线仅包含末尾逗号，由工具的 `AllowTrailingCommas` 容错规则正确接收。因此后续以 10,018 条作为可复现的权威候选数。

这些绝对路径只作为首轮验收输入，不写死到应用配置或源码中。正式工具接受任意一个或多个用户选择的目录。

## 目标与非目标

### 目标

- 递归扫描一个或多个路线根目录。
- 宽容解析 BetterGI `PathingTask` JSON，跳过 `process.json` 等非路线文件。
- 使用统一坐标转换接口把游戏坐标转换为路网使用的地图图像坐标。
- 在传送点处断开路线，把连续路点转换成可规划的图边。
- 吸附相近节点、合并重复路线与重复边，使不同脚本仓库的重叠路线形成连通路网。
- 避免通用导航意外执行战斗、采集、挖矿等副作用动作。
- 将历史路线与已有遥测路段合并到同一个 `route_navigation_graph.json`。
- 在地图窗口提供明确的批量导入入口和可理解的成功、跳过及失败统计。
- 支持通过同一核心 API 进行无界面批量构图，以便完成首轮真实数据生成和以后自动化更新。

### 非目标

- 不修改原脚本仓库文件。
- 不把历史路线伪装并写入 `*_Telemetry.json`。
- 不在本阶段推断地图高度、地下层级或道路可见性。
- 不自动执行生成的路网；实机移动仍由 P9 验收完成。
- 不把首轮生成的大型路网 JSON 提交到 Git。

## 架构

### `PathingTaskRouteImporter`

负责文件发现、解析、标准化和报告，不负责写图：

- 输入：有序、去重后的源目录集合和导入选项。
- 输出：`RouteNavigationSourceSegment` 集合与 `PathingTaskImportReport`。
- 文件按完整路径稳定排序，确保相同输入得到确定性结果。
- 先按规范化路线签名去重，再进行坐标转换，避免多个仓库的同一条路线重复膨胀路网。
- 解析失败、无 `positions`、少于两个有效点、未知地图、坐标转换失败均记录分类计数和有限数量的示例路径；单个坏文件不会中止整个批次。

### `RouteNavigationSourceSegment`

作为遥测与历史路线共享的中间模型，包含：

- 地图名；
- 起点、终点和折线点；
- 移动模式与允许保留的导航动作；
- 传送锚点；
- 来源类型、来源文件和稳定来源标识；
- 可逆性与基础成本数据。

现有 `RouteTelemetryRecord` 通过适配器转换为该模型；历史 `PathingTask` 不再伪造遥测时间、成功率或健康记录。

### `RouteGraphNodeSnapIndex`

按地图维护空间哈希索引，以 6 个地图图像像素为默认吸附半径：

- 只在同一地图内吸附；
- 搜索当前网格及相邻网格，避免全量两两比较；
- 节点坐标采用稳定的首个锚点，不随扫描顺序以外的浮点累计变化；
- 不允许一条边的终点吸附回它自己的起点，过短或重复路点直接跳过；
- 节点 ID 从吸附后的地图名与坐标生成，保持构建结果稳定。

6 像素约等于提瓦特地图中的 3 个游戏坐标单位，足以合并录制漂移，同时降低把相邻平行道路误并的风险。该值保留为构建选项，首轮 UI 不增加高级参数。

### `RouteNavigationGraphBuilder`

构建器改为接受 `RouteNavigationBuildRequest` 并返回 `RouteNavigationBuildResult`：

1. 加载已有遥测并转换为统一路段。
2. 加载所选历史路线目录并转换为统一路段。
3. 对路段端点进行空间吸附。
4. 按地图、吸附后起终点、移动模式和安全动作合并重复边。
5. 根据现有规则为步行、奔跑、冲刺和游泳路段生成反向边；飞行、跳跃、攀爬和四叶印路段保持单向。
6. 原子写入临时文件并替换 `route_navigation_graph.json`。

自动遥测触发的后台重建保持原行为，只使用遥测源；只有用户显式执行“从已有路线生成路网”时才扫描外部历史目录。

## 路线转换规则

### 坐标

- `PathingTask.positions[].x/y` 视为原神游戏坐标。
- 唯一转换入口是 `IRouteCoordinateConverter.TryGameToImage`。
- 地图名为空时按 `Teyvat` 处理；无法识别的非空地图名不猜测，直接跳过并报告。
- 不允许把游戏坐标直接写进图节点或边。

### 分段和传送

- 每两个连续有效路点形成一个候选路段，使规划器可以在历史路线中途接入和离开，而不是只能使用整条路线的首尾。
- 遇到 `type=teleport` 时断开上一段，不生成跨传送的普通边。
- 传送路点成为新分段起点，并生成与现有格式一致的 `TP_<round(gameX)>_<round(gameY)>` Anchor；后续规划器仍使用现有传送点数据校验其可用性。
- 连续传送点、重复坐标和转换后零长度路段直接跳过。

### 动作安全

历史路线仅保留通用导航必需动作：

- `stop_flying`
- `up_down_grab_leaf`

战斗、战斗脚本、采集、挖矿、拾取、设置时间、重登、强制传送、交互传送及未知动作全部从导入边中清除，但保留其几何路线。导入报告统计被清除动作的类型和数量。这样从地图点击目标生成的临时任务不会因为复用采集路线而意外执行其业务动作。

### 去重与来源

- 路线签名由规范化地图名和完整路点序列生成，不依赖文件名或仓库路径。
- 图边签名由地图、吸附后的起终节点、移动模式和安全动作生成。
- 重复边保留确定性的代表折线，并累计 `SourceCount`。
- 图 Schema 升级时新增 `SourceKind`、`SourceCount` 和有限来源摘要；旧图缺少这些字段时仍可由 Provider 读取。

## 用户界面

地图窗口的路网调试区新增带文字的“从已有路线生成路网”按钮，不隐藏在仅有图标的小按钮中：

1. 打开支持多选的文件夹选择器；默认定位到当前 `User/AutoPathing`。
2. 用户选择一个或多个脚本仓库路线目录。
3. 后台扫描、转换和写图，期间禁用重复构建命令并显示“正在扫描/转换/写入”。
4. 完成后刷新 Graph Provider 和地图诊断。
5. `GraphSummary` 显示文件数、有效路线、重复路线、节点、边、跳过文件、清除动作和输出路径。
6. 无有效路线、全部转换失败或写文件失败时，同时更新状态并使用 `ThemedMessageBox` 显示明确原因。

原“重建路网”按钮继续作为只从遥测重建的开发调试功能。

## 批处理入口与首轮生成

核心构建请求不依赖 ViewModel，可由测试或轻量批处理宿主直接调用。首轮生成使用上面的四个源目录，输出到本分支 Debug 可执行目录对应的：

`User/AutoPathing/Routes/route_navigation_graph.json`

同时记录文件大小、SHA-256、各地图节点/边数量、最大连通分量和跳过原因摘要。生成物属于本地派生数据，不进入 Git；源码、测试和设计文档进入 Git。

## 错误处理

- 不存在或不可读目录：该目录计入失败；若仍有其他有效目录则继续。
- 单文件 JSON 或模型错误：跳过文件并记录示例，不终止批次。
- 单路点坐标转换失败：只断开该处相邻路段；其余有效路段继续导入。
- 没有产生任何边：不覆盖现有图文件，并返回失败结果。
- 写入失败：保留旧图，删除临时文件，并返回输出路径和系统错误。
- 用户取消：停止尚未开始的后续阶段，不替换旧图。
